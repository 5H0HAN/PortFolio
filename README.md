# Shohan Biswas Portfolio

A modern portfolio for Shohan Biswas, focused on Google Workspace, email
infrastructure, DNS authentication, migrations, deliverability, and practical
backend engineering.

The project is built with the Next.js App Router and keeps the portfolio,
Markdown blog, public DNS tools, service proof, and SEO infrastructure in one
deployable application.

## Highlights

- Responsive portfolio with coordinated light and dark themes
- Google Workspace and email infrastructure service pages
- Google Workspace Setup Checker with custom DKIM selector support
- Mail Deliverability DNS Test with transparent scope and limitations
- In-repository Markdown blog without WordPress or an external CMS
- Fiverr review snapshot and services-page review carousel
- Canonical metadata, Open Graph cards, JSON-LD, sitemap, robots rules, and RSS
- Accessible navigation, reduced-motion support, and keyboard focus states

## Technology

- Next.js 15 (App Router)
- React 18
- TypeScript
- Markdown with `gray-matter`, `react-markdown`, and `remark-gfm`
- Keystatic for content editing
- Server-side DNS diagnostics
- CSS design system with responsive layouts and theme tokens
- pnpm

## Getting Started

### Requirements

- Node.js 20 or newer
- pnpm 10 or newer

Enable pnpm through Corepack if it is not already available:

```bash
corepack enable
```

Install dependencies and start the development server:

```bash
pnpm install
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000).

## Environment

Copy the example environment file when you need to override the production URL:

```bash
cp .env.example .env.local
```

| Variable | Purpose | Default |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Canonical site URL used by metadata, JSON-LD, sitemap, RSS, and social images | `https://shohanbiswas.com` |
| `RESEND_API_KEY` | Optional Resend API key for direct contact-form delivery | Not set; mail-app fallback remains active |
| `CONTACT_FROM_EMAIL` | Verified sender used by the contact API | Not set |
| `CONTACT_TO_EMAIL` | Contact-form destination | `hello@shohanbiswas.com` |
| `NEXT_PUBLIC_KEYSTATIC_STORAGE_KIND` | Set to `github` locally during the one-time GitHub App setup | `local` |
| `KEYSTATIC_GITHUB_CLIENT_ID` | GitHub App client ID for the production content studio | Generated by Keystatic |
| `KEYSTATIC_GITHUB_CLIENT_SECRET` | GitHub App client secret | Generated by Keystatic |
| `KEYSTATIC_SECRET` | Secret used to protect Keystatic sessions | Generated by Keystatic |
| `NEXT_PUBLIC_KEYSTATIC_GITHUB_APP_SLUG` | Public slug of the connected GitHub App | Generated by Keystatic |

No credentials are required for the public tools. They inspect public DNS
records and do not modify domain or Google Workspace settings.

## Content Studio

Keystatic is available at `/keystatic`.

- Local development edits Git-tracked content files directly.
- Production uses authenticated GitHub mode for `5H0HAN/PortFolio`.
- Production saves are Git-backed content changes, not writes to a separate database.
- Only GitHub users with write access to the repository can enter the production studio.

The studio manages field notes, external article media, profile and education
details, social links, marketplace proof, skills, operating principles,
services, and projects. Layout, tools, and application behavior remain in code.

For the first production setup, set
`NEXT_PUBLIC_KEYSTATIC_STORAGE_KIND=github` in `.env.local`, open local
`/keystatic`, create or connect the prompted GitHub App, and grant it access to
this repository. Copy the four generated Keystatic variables into the deployment
environment. Production deliberately returns `404` for `/keystatic` and `503`
for its API until all four variables exist, allowing the public site to deploy
safely before the editor is connected.

### External article media

Each article can include one optional lead asset without storing media in this
repository:

- `Image` or `Animated GIF`: use an HTTPS direct asset URL from a public host.
- `Direct video file`: use an HTTPS browser-playable video asset URL.
- `YouTube video`: use a standard watch, share, Shorts, live, or embed URL.

For Imgbox and Giphy, use the direct image or GIF URL rather than the surrounding
webpage URL. YouTube links use the privacy-enhanced `youtube-nocookie.com`
player. Arbitrary iframe providers and non-HTTPS media are not rendered.

## Publishing an Article

Use `/keystatic` for routine publishing, or create a Markdown file in
`content/blog` when working directly in Git. The filename is the article slug:

```yaml
---
title: "Article title"
date: "2026-07-30"
excerpt: "A concise description for readers and search results."
category: "Email Infrastructure"
tags: ["Google Workspace", "SPF", "DKIM", "DMARC"]
author: "Shohan Biswas"
featured: false
published: true
mediaType: "none"
---
```

Write the article below the frontmatter. Published articles automatically appear
on the blog, in related-post suggestions, in the sitemap, and in the RSS feed.
Set `published: false` to retain a local draft without exposing it publicly.

## Public Tools

### Google Workspace Setup Checker

Checks public Google verification TXT, Google Workspace MX, SPF, DKIM, and
DMARC records. The DKIM lookup accepts the Google default selector or a custom
selector.

### Mail Deliverability Test

Assesses public MX routing and sender-authentication posture. It is intentionally
presented as a DNS-readiness assessment, not a promise of inbox placement.

Neither tool signs in to Google Workspace, sends email, or changes DNS records.

Public diagnostic requests are validated, briefly cached, timed out, and protected
by a bounded per-instance rate limit. For globally coordinated production rate
limits, add a Vercel Firewall rule or an external rate-limit store.

## Contact Form Delivery

The contact form keeps its mail-app fallback unless direct delivery is fully
configured. To enable direct delivery:

1. Verify a sending domain with Resend.
2. Set `RESEND_API_KEY` in Vercel.
3. Set `CONTACT_FROM_EMAIL` to a sender on the verified domain.
4. Optionally set `CONTACT_TO_EMAIL`; it defaults to the public profile email.
5. Redeploy and submit a test message.

The API validates input, uses a honeypot, limits requests, sends plain text only,
and applies an idempotency key to reduce accidental duplicate delivery.

## SEO and Discovery

- `/sitemap.xml` includes portfolio pages, tools, and published articles.
- `/robots.txt` allows public pages and excludes internal API endpoints.
- `/feed.xml` publishes the article feed.

- JSON-LD describes the portfolio owner, services, tools, blog, and articles.

## Deployment

The application can be deployed to any platform that supports Next.js. Set
`NEXT_PUBLIC_SITE_URL` to the final HTTPS origin before building so canonical
URLs and structured data use the correct domain. The production content studio
also requires a Node.js-capable host and the four Keystatic GitHub App variables
listed above.

For Vercel:

1. Import `5H0HAN/PortFolio`.
2. Select pnpm when prompted.
3. Add `NEXT_PUBLIC_SITE_URL=https://shohanbiswas.com`.
4. Deploy the public site.
5. Complete the GitHub App setup locally as described above.
6. Add the four generated Keystatic variables to Vercel and redeploy.
